# Phase 2 — события и локации (Book Intelligence, второй проход)

## Что добавлено
- **Второй проход анализа** `story_elements`: по каждому фрагменту извлекаются события и локации.
  Запускается автоматически после завершения анализа персонажей (`STORY_AUTO_ENQUEUE=true`)
  или вручную: `POST /api/v1/books/{id}/analyze/story-elements` (`?force=true` — повторно).
- Отдельный проход, а не расширение первого: уже проанализированные книги не нужно пересчитывать,
  а участники событий привязываются к реальным персонажам из базы.
- Модели получают контекст: самые упоминаемые персонажи книги (с псевдонимами) и известные локации
  проекта — чтобы использовать уже зафиксированные имена.

## Качество данных
- Каждое событие, атрибут и упоминание локации подтверждено **дословной цитатой**; цитата не найдена
  в тексте → факт отброшен (`rejected_evidence` в отчёте задачи).
- Позиции цитат хранятся **абсолютными в главе** → дубли из зоны перекрытия фрагментов (500 символов)
  отбрасываются (`events_duplicate`), упоминания локаций уникальны по позиции.
- Локации: точное совпадение имени/алиаса → сопоставление; похожее, но не точное → не объединяется,
  попадает в `report.ambiguous` на ручную проверку.
- Второй проход **не создаёт персонажей**: неопознанный участник сохраняется с `match_status=unknown|ambiguous`.
- Неизвестные значения типов (event_type, location_type…) приводятся к значению по умолчанию,
  а не вызывают платный повтор запроса.
- Порядок событий: `timeline_position = номер главы × 10⁹ + позиция цитаты` (порядок повествования).

## Надёжность (как в Phase 1.5)
Та же очередь: lease, повторы с backoff, пауза при проблемах ключа/баланса, `resume` доделывает только
незавершённое, ответ LLM кэшируется в задаче (падение после ответа — повторно не платим).
Расход второго прохода — операция `extract_story_elements` в `ai_usage`.

## API
- `GET  /api/v1/books/{id}/events?chapter_number=&importance=&event_type=&character_id=&location_id=`
- `PATCH /api/v1/events/{id}` — правка / `status: confirmed|rejected`
- `GET  /api/v1/projects/{id}/locations`, `GET /api/v1/locations/{id}` (атрибуты, упоминания, события)
- `PATCH /api/v1/locations/{id}` — переименование (старое имя сохраняется алиасом), тип, статус
- `GET  /api/v1/books/{id}/analysis-jobs` и `GET /api/v1/analysis-jobs/{id}` — теперь с `job_type`

## Фронтенд
- Исправлено: прогресс анализа «замирал» — опрос шёл только для статусов `pending/running`,
  а очередь Phase 1.5 использует `queued/paused`.
- При выборе книги подгружается её последняя задача; после персонажей экран сам переключается
  на второй проход. Показывается стоимость, у задачи на паузе — кнопка «Продолжить».
- Новый раздел «Хроника книги»: события (фильтры, участники, место, цитата, подтвердить/отклонить)
  и карточки локаций.

## Запуск
`docker compose up -d --build` — backend применит миграцию `20261120phase2`.
Для уже проанализированных книг: кнопка «Извлечь события и локации» или POST-запрос выше.

## Стоимость
Второй проход ≈ ещё столько же запросов к LLM, сколько фрагментов в книге (плюс контекст ~1–2 тыс.
токенов на запрос). Отключить автозапуск: `STORY_AUTO_ENQUEUE=false`.

## Тесты
`DATABASE_URL=... RUN_DB_TESTS=1 pytest backend/tests` — 16 тестов (4 новых: полный конвейер с
отсевом дублей, падение воркера после ответа LLM, API, запрет второго прохода без персонажей).

## Ограничения
- Мировые факты, сюжетные линии и стиль — Phase 3 (Knowledge Base & Story Bible) по roadmap.
- Объединение похожих локаций — вручную (переименование/отклонение); автослияния нет намеренно.
- Ответ LLM, полученный в момент `kill -9`, провайдер спишет, но в `ai_usage` он не попадёт (как в Phase 1.5).
